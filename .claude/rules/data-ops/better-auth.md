# Better Auth Rules

## Configuration

- Configure options (plugins, session, user fields) in `createBetterAuth()` in `packages/data-ops/src/auth/setup.ts`
- The Worker gets its instance through `setAuth()` / `getAuth()` in `packages/data-ops/src/auth/server.ts`; `packages/data-ops/config/auth.ts` builds one only for `better-auth:generate`
- Never edit `auth-schema.ts` (auto-generated by `better-auth:generate`)
- Use plugins for extended features (2FA, OAuth, etc.)

## Database Integration

- Use Drizzle adapter for this project
- Run `pnpm better-auth:generate` after config changes
- Migrations handled via Drizzle

## Session Management

- `session.expiresIn` (seconds): time until session expires. Default = `604800` (7 days). **No disable option** — must be a positive number. Max value: `34560000` (400 days) — enforced by `better-call` cookie serializer.
- `session.updateAge` (seconds): rolling refresh threshold. Default = `86400` (24 hours). On each `getSession` call, if remaining lifetime < `updateAge`, expiry is extended by another `expiresIn`.
- Session policy for this project: **no automatic expiry for active users** — sessions are valid indefinitely as long as the user is active (rolled daily). Revoke manually by deleting row from `auth_session`. `expiresIn` capped at 400 days (RFC 6265 limit enforced by `better-call@1.3.2+`).

```ts
session: {
  modelName: "auth_session",
  expiresIn: 60 * 60 * 24 * 400, // 400 days — RFC 6265 cookie Max-Age limit
  updateAge: 60 * 60 * 24,       // refresh daily
}
```

## Extending Schema

- Add custom fields via `additionalFields`
- Use `input: false` for server-only fields

```ts
user: {
  additionalFields: {
    role: {
      type: 'string',
      required: true,
      defaultValue: 'user',
      input: false, // server assigns, not user
    },
  },
}
```

## Security

- Never expose auth secrets in client code
- Use HTTP-only cookies for session tokens
- Implement rate limiting on auth endpoints
- Revoke sessions on password change
